# Архітектура

Обов’язкові вимоги до змін: [coding-standards.md](./coding-standards.md).

## Стек і межі

Next.js 16.4.0 App Router, React 19.3, TypeScript 7, ESLint 9, CSS Modules.
Маршрути в `src/app` компонують сторінки; бізнес-логіка зберігається у
`src/features/catalog`, `cart`, `checkout`, `business`, `customer-account`,
`home` та `favorites`.
Спільний layout містить шапку, `main#main-content` і підвал.

CRM є джерелом каталогу, цін, залишків, замовлень, платежів і доставки.
`src/lib/crm-client.ts` виконує серверні запити й повертає `unknown`;
адаптери перевіряють відповіді схемами Zod. Секрети захищені `server-only`.
Взаємодія браузера з бізнес-логікою використовує Server Functions / Actions.

## Бібліотеки

- React Hook Form, Zod, resolvers — форми та спільна валідація.
- react-select — доступні поля пошуку міста, відділення й вулиці.
- SWR, use-debounce — довідники, пошук і перевірка оплати.
- Iron Session — зашифровані сесії та токени оформлення/повернення.
- sanitize-html — очищення HTML описів; текстові теги без атрибутів.
- nuqs — стан фільтрів каталогу в URL.

## Дані й кеш

Загальні списки каталогу використовують `"use cache"`, `cacheLife("minutes")`
і теги `catalog`, `catalog:collection:<slug>`. Персональні дані та актуальні
перевірки товару, кошика й checkout виконуються поза цим кешем.
CRM транспорт використовує `cache: "no-store"`.
Неповна або некоректна пагінація завершує читання помилкою.

Cookie `cjp_cart` містить лише позиції `{p: variantId, q: quantity}`.
Ціни й доступність щоразу беруться з CRM. Нульовий залишок не приховує товар,
але забороняє покупку. `stock: null` означає, що облік кількості не ведеться.
Сума обчислюється в цілих копійках із перевіркою безпечного діапазону.

## Checkout і оплата

Checkout перевіряє актуальний кошик, суму, доступні способи та refs адреси.
Якщо сума або кількість змінилися, покупець підтверджує оновлену форму.
Захищений токен форми забезпечує однаковий externalId для паралельних повторів
того самого запиту; завершена покупка не блокує нове замовлення з нової форми.
CRM присвоює номер замовлення й створює посилання Monobank.

Повернення використовує `/checkout/success?token=…`; токен дає доступ лише до
одного замовлення протягом 24 годин. Статус і сума читаються з CRM.
Без cookie замовлення відновлюється через токен; сесія записується лише в Server Action.
Відсутній/нечинний токен і відсутня сесія показують відновлення, а не 404.
Затримка банку показує індикатор і перевірку кожні 5 секунд до хвилини.

Локального журналу замовлень, банківського callback і mock-провайдерів немає.
Webhook банку та створення ТТН належать CRM. Подробиці: [crm-checkout.md](./crm-checkout.md).

## Запит на оптовий доступ (B2B)

`/business` — форма запиту для зоомагазинів, грумерів, ветклінік. Заявка
стає лідом CRM із джерелом `partner` (`POST /leads`, `source: "partner"`),
окремо від роздрібних звернень. Ключ ідемпотентності `b2b-<uuid>` генерує
браузер один раз на форму, тож повторне натискання не створює дубль.
Менеджер узгоджує умови, оформлює контрагента й запрошує партнера до
кабінету партнера в CRM. Посилання «Увійти до кабінету партнера» й «Ввести
код» ведуть на `PARTNER_PORTAL_URL` (за замовчуванням
`https://obriym-crm.com/portal`).

Кабінет роздрібного покупця на сайті не будується: це функція Obriym CRM на
адресі магазину (`{shop}.obriym.app`). Варіант кабінету в дизайні сайту
лежить у гілці `feature/customer-cabinet` як платна кастомна доробка.

Адресу кабінету сайт не зберігає: її віддає CRM у `GET /capabilities` →
`customerAccount.url`, лише поки кабінет відкритий (`null`, якщо його вимкнено
чи не налаштовано). Іконка «Особистий кабінет» у шапці й пункт мобільного меню
з’являються тільки тоді. Відповідь кешується як каталог (`minutes`), тож
вмикання й вимикання в CRM доходить до сайту за кілька хвилин без релізу.
Якщо CRM недоступна, шапка рендериться без іконки
(`src/features/customer-account/queries.ts`).

## Семантика й перевірки

Нативні форми, кнопки, списки, таблиці й заголовки; контакти — `address`,
характеристики замовлення — `dl/dt/dd`. Поля підтримують клавіатуру,
прив’язані назви, повідомлення та фокус помилок.

Перевірки: `npm run typecheck`, `npm run lint -- --max-warnings 0`, `npm test`.
Browser QA, callback банку, production і база даних потребують окремих доказів.
Production build виконується лише за прямим запитом користувача.
