# Архітектура

Довідка для тих, хто продовжує роботу над магазином. Вимоги — у [init.md](./init.md).

## Стек

Next.js 16 (App Router) з увімкненим `cacheComponents`, React 19, TypeScript, CSS Modules.
Зовнішніх залежностей немає — лише `server-only` як межа між сервером і клієнтом.

## Структура

```
src/
  app/          маршрути (тонкі: композиція + метадані, без бізнес-логіки)
  components/   layout (шапка, підвал) та ui-примітиви (Button, Badge, Price, Section)
  features/     catalog · cart · checkout · home — кожна тримає свої дані, дії та компоненти
  content/      текстові сторінки (доставка, оплата, оферта, розміри)
  lib/          money, form, navigation, site
```

Правило: маршрут нічого не знає про джерело даних, фіча нічого не знає про маршрут.

## Кешування

Каталог статичний для всіх відвідувачів, кошик — ні. Звідси поділ:

| Дані | Механізм | Де |
| --- | --- | --- |
| Товари, категорії, колекції, розміри | `"use cache"` + `cacheLife` + `cacheTag` | `features/catalog/queries.ts` |
| Кошик, підтвердження замовлення | `cookies()` за межами кешу | `features/cart`, `features/checkout` |

Усе, що читає cookie, обгорнуте в `<Suspense>` — тому кожен маршрут віддає статичну оболонку,
а персональна частина доїжджає стрімом. `next build` показує це як `◐ Partial Prerender`.

Теги для інвалідації: `catalog`, `catalog:product:<slug>`, `catalog:category:<slug>`.
Після підключення CMS/CRM мутація викликає `updateTag("catalog")`.

## Кошик без реєстрації

Cookie `cjp_cart` (httpOnly, 30 днів) зберігає лише `{ productId, size, quantity }`.
Ціни ніколи не беруться з cookie — `buildCart` щоразу звіряє позиції з каталогом,
відкидає зниклі товари й обрізає кількість до залишку. Зіпсована cookie = порожній кошик, не помилка.

Мутації — Server Actions у `features/cart/actions.ts`. Зміна кількості й видалення
працюють звичайними формами, тобто без JavaScript теж.

## Точки для інтеграцій

Три місця, які змінюються при підключенні зовнішніх сервісів — і більше нічого:

| Що підключаємо | Файл |
| --- | --- |
| CMS або товарний фід замість сід-даних | `features/catalog/catalog-source.ts` |
| SalesDrive (створення замовлення) | `features/checkout/order-repository.ts` |
| Еквайринг (LiqPay / Mono) | `features/checkout/payment/` — реалізувати `PaymentProvider` |

Наразі оплата працює в ручному режимі: замовлення фіксується, менеджер надсилає посилання
на оплату. Накладений платіж і рахунок для ФОП працюють повністю.
