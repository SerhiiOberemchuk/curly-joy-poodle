# Деплой на Vercel

Сайт живе на Vercel. Репозиторій підключений до проєкту Vercel: кожен push у
`main` збирає production, кожна інша гілка — preview. Окремих налаштувань
збірки не потрібно, Vercel сам розпізнає Next.js.

## Змінні оточення

Vercel → Project → Settings → Environment Variables. Для production:

| Змінна | Значення |
| --- | --- |
| `SITE_URL` | `https://curly-joy.com`, без `/` в кінці. З нього будуються адреси повернення й callback LiqPay. |
| `OBRIYM_CRM_API_KEY` | Токен з акаунта клієнта в obriym-crm (скоуп `products:read`). Звідси береться весь каталог. |
| `LIQPAY_MODE` | `sandbox` або `live` (`mock` — лише для локальної розробки). |
| `LIQPAY_PUBLIC_KEY`, `LIQPAY_PRIVATE_KEY` | Ключі з кабінету LiqPay. Для `sandbox` — тестові. |
| `CRM_MODE` | `off`. `mock` лише імітує передачу замовлення в CRM і пише payload у лог. |

`OBRIYM_CRM_API_URL` задавати не треба: за замовчуванням це
`https://obriym-crm.com/api/v1`. `ORDER_STORE_DIR` на Vercel не має сенсу — див.
нижче.

Нові значення змінних діють з наступного деплою: після зміни натисніть
Deployments → Redeploy.

## Каталог із CRM

`next build` пререндерить каталог, тому `OBRIYM_CRM_API_KEY` потрібен **і під час
збірки**. Без нього або коли CRM недоступна, збірка падає, і на сайті лишається
попередній деплой.

Після деплою каталог оновлюється сам: дані з CRM кешуються на хвилину, тож
товар, доданий чи змінений у CRM, з'являється на сайті за 1–2 хвилини без
нового деплою.

## Домен

Vercel → Settings → Domains: додайте `curly-joy.com` і `www.curly-joy.com`.
Vercel покаже, які DNS-записи потрібні. Внесіть їх у DNS-зоні домену. Міняйте
лише записи сайту (A для `curly-joy.com`, CNAME для `www`): MX і TXT пошти не
чіпайте, інакше зупиниться пошта на домені. HTTPS-сертифікат Vercel випускає
сам, щойно записи почнуть вказувати на нього.

## Обмеження: журнал замовлень

Замовлення поки що пишуться в JSON-файли (`order-repository.ts`). На Vercel
файлова система доступна лише для читання, тому сховище працює тільки в пам'яті
одного інстансу: callback LiqPay може прийти в інший інстанс і не знайти
замовлення. Тому замовлення й оплата переїжджають у CRM клієнта: магазин
створює замовлення через `POST /orders` і отримує посилання на оплату monobank
через `POST /orders/{externalId}/payment-link`, а callback банку приймає сама
CRM. Для цього клієнт має спершу підключити monobank у своїй obriym-crm.
Деталі поточної схеми — у [liqpay.md](./liqpay.md#журнал-замовлень).

## Перевірка після деплою

- Головна, каталог і картка товару відкриваються, товари й фото — з CRM.
- `https://curly-joy.com/api/payments/liqpay/callback` відповідає `405` на `GET`,
  тобто доступний з інтернету.
- Товар додається в кошик, оформлення доходить до сторінки оплати.

## Передача проєкту

Проєкт Vercel можна передати в іншу команду: Settings → General → Transfer
Project. Код лежить у GitHub, а повний список змінних оточення — у таблиці
вище, тож сайт можна розгорнути й на іншому хостингу з підтримкою Next.js.
